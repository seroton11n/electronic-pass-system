# UC-04. Просмотр электронного пропуска

## 1. Контекст использования

Родителю (законному представителю) необходимо получить электронный пропуск учащегося, чтобы передать его ребёнку для предъявления сотруднику охраны при выходе за территорию гимназии-интерната.

## 2. Область действия

Веб-приложение «Электронный пропуск».

## 3. Основное действующее лицо

Родитель (законный представитель).

## 4. Участники

Отсутствуют.

## 5. Предусловия

1. Родитель (законный представитель) авторизован в системе.
2. Заявка на выход учащегося прошла все этапы согласования и получила окончательный статус «Одобрено».
3. Электронный пропуск с QR-кодом сформирован в системе и доступен родителю.

## 6. Гарантии успеха

1. Родителю доступен для просмотра электронный пропуск с QR-кодом.
2. Родитель может скачать электронный пропуск на своё устройство.
3. Родитель может поделиться электронным пропуском.

## 7. Триггер

Родитель (законный представитель) открывает раздел «Активные заявки» и выбирает одобренную заявку, для которой необходимо просмотреть электронный пропуск.

## 8. Основной сценарий

1. Родитель открывает раздел «Активные заявки».
2. Система отображает список заявок, созданных данным родителем.
3. Родитель выбирает заявку, по которой необходимо просмотреть электронный пропуск.
4. Система отображает подробную информацию по выбранной заявке.
5. Родитель выбирает действие «QR-пропуск».
6. Система отображает электронный пропуск с QR-кодом и информацией об учащемся: ФИО, класс, дату и время выхода, дату и время возвращения, срок действия пропуска.
7. При необходимости родитель выбирает действие «Скачать».
8. Система сохраняет QR-пропуск на устройство родителя.
9. При необходимости родитель выбирает действие «Поделиться» и отправляет QR-пропуск выбранным способом.
10. Родитель закрывает электронный пропуск.
11. Система возвращает родителя на страницу с подробной информацией по выбранной заявке.

## 9. Альтернативные сценарии (расширения)

### 2а, 4а, 6а, 8а. Возникают технические неполадки при выполнении операции.

1. Система обнаруживает техническую ошибку при выполнении операции.
2. Система сообщает родителю о возникновении технических неполадок.
3. Система предлагает повторить попытку позднее.
4. Выполнение сценария завершается.
## Правило автоматического изменения статуса заявки

По истечении срока действия электронного пропуска система автоматически проверяет наличие зафиксированного фактического выхода учащегося.

Если фактический выход не был зафиксирован, система присваивает заявке статус «Истёк срок действия».

Если фактический выход был зафиксирован, статус заявки не изменяется. Заявка ожидает фиксации фактического возвращения учащегося.
